# Vismay (विस्मय)

**Explore. Understand. Stay Curious.**

Vismay is a curiosity-first personal learning companion. Start with one question, learn at your preferred depth, consult real sources, preserve your exact journey of discovery, and return naturally to continue — within a beautifully atmospheric, minimal, real, performant web app.

This is **not** a research dashboard, a course platform, an RPG, or a generic chatbot. It is a quiet, knowledgeable learning assistant that reacts to your curiosity instead of steering it.

> The user controls curiosity. The AI supports it.

---

## Stack

- **Next.js 16** (App Router) + **React** + **TypeScript** (strict)
- **Tailwind CSS 4** + **shadcn/ui** (New York)
- **Motion for React** (`motion/react`) — hero reveals, parallax, line drawing, accordions, drawer
- **Prisma ORM** with **SQLite** (sandbox) — the schema is portable to PostgreSQL/Supabase; just swap the `datasource` provider and add RLS policies server-side
- **z-ai-web-dev-sdk** for server-side AI (`chat.completions`, `web_search`, `page_reader`). The same provider surface can be backed by OpenAI or Gemini in self-hosted deployments by setting env vars
- **Zustand** for client-side view-state (the app is a single-route SPA — the user-visible URL is `/`)

## Light theme — only

Vismay is built as a single, deliberate light theme. There is **no dark mode, no theme toggle, no `.dark` CSS, no `dark:` Tailwind variants.** Eye-comfort features may be revisited in the future, but the current build intentionally ships light-only.

## Ambient background art — real assets, not a screenshot

The hero and topic pages use three transparent SVG layers — `misty-landscape.svg`, `observatory-arch.svg`, `celestial-lines.svg` — placed in `/public/visuals/`. They are rendered by `src/components/vismay/ambient/VismayAmbientScene.tsx` as independent parallax layers (landscape ~10%, arch ~6%, celestial ~16% of scroll displacement), animated with Motion's `useScroll` + `useTransform`. The homepage uses `intensity="full"`; the topic reading page uses `intensity="calm"` (lower opacity, only celestial + a hint of landscape). All decorative artwork respects `prefers-reduced-motion`.

## Information architecture

A single `/` route drives a client-side view-state router (`useVismayStore`). Views:

| View                | Purpose                                                            |
| ------------------- | ----------------------------------------------------------------- |
| **Home**            | Search-first hero, Continue Learning card, journey preview.       |
| **Topic**           | Three-column reading layout: sections sidebar, main column with accordion sections, right sidebar with assistant + sources. |
| **My Learning**     | Saved and ongoing topics, with filter chips and search.           |
| **Journey**         | Chronological learning history — exactly how one idea led to another. |
| **Connected Concepts** | Logical knowledge graph (force-directed SVG) — separate from chronology. |
| **Library**         | All saved sources with tier/kind filters and real external links. |
| **Notes**           | Two-pane notes editor.                                            |
| **Uploads**         | Drag-and-drop file uploads + source-based Q&A on extracted text.  |

## The two truths — chronology and connection

Vismay preserves **two separate truths** about your learning:

1. **My Learning Journey** — the exact chronological route you took. Stored as durable time-stamped `LearningEvent` rows (`topic_started`, `section_opened`, `subtopic_explored`, `source_viewed`, `explanation_requested`, `visual_viewed`, `challenge_attempted`, `note_saved`, `discovery_followed`, `topic_resumed`). Never rearranged by the AI.
2. **Connected Concepts** — an opt-in logical knowledge graph (`ConceptNode` + `ConceptEdge`) showing conceptual relationships and prerequisites. Generated by the AI when you start a topic, and editable.

Neither replaces the other. The Journey replays how you got here. The Concept Graph shows how ideas relate.

## AI assistant — quiet by design

The assistant is **integrated into the learning workspace**, not isolated as a chat page. It:

- Offers **at most one or two contextual suggestions** per view.
- Opens a **slide-in drawer** on the right (does not cover reading content on desktop).
- Records a `topic_started` event when you ask a new question — but **never marks content as "mastered"** just because you opened it.
- Adapts to your preferences (concise / examples / detailed / exploratory; beginner / balanced / advanced; show diagrams; show citations).
- When you select text on a topic page, a floating action menu offers: **Explain, Go Deeper, Visualize, Find Sources, Challenge Me, Connect, Save** (Visualize only for visual-friendly domains; Connect only if you have prior learning).

## Sources and research — user-controlled scope

- A **lightweight factual lookup** is the default.
- **Deeper discovery is opt-in** — the user explicitly chooses the scope (light / deep) and the kinds of sources they want.
- The retrieval pipeline: `query plan → web_search → page_reader (top hits) → split into passages → rank by relevance → grounded answer with citations`.
- Each saved source has a **tier** (primary / secondary / commentary / uncertain / conflicting / unchecked) and **kind** (constitution / legislation / judgment / textbook / article / paper / video / upload / other).
- The AI is **never** allowed to fabricate citations, page numbers, case names, or dates. If a claim isn't backed by a retrieved passage, the response says so.
- Retrieved web text is treated as **untrusted content** — wrapped in quoted blocks with explicit instructions forbidding the model from treating it as commands.

## Uploads

Drag-and-drop a PDF, TXT, MD, or DOCX (max 10 MB). For text/markdown, the text is extracted and indexed; you can ask source-grounded questions with passage citations. For PDFs and DOCX, the metadata is stored honestly with a note that full text extraction is on the roadmap.

## Getting started

### Prerequisites

- Node.js 20+ or Bun 1.3+
- (Sandbox) The z-ai-web-dev-sdk reads credentials from `/etc/.z-ai-config`. No env vars required.
- (Self-hosted) Set `ZAI_API_KEY` + `ZAI_BASE_URL` (or `OPENAI_API_KEY`) in `.env`. Copy `.env.example` to `.env`.

### Install & run

```bash
bun install                 # or npm install
bun run db:push             # create the SQLite database
bun scripts/seed.ts         # optional — inserts DEMO-labeled seed data
bun run dev                 # http://localhost:3000
```

### Scripts

| Script                  | Purpose                                              |
| ----------------------- | ---------------------------------------------------- |
| `bun run dev`           | Start the dev server (port 3000).                    |
| `bun run lint`          | ESLint (Next.js + TypeScript rules).                |
| `bun run db:push`       | Push the Prisma schema to SQLite.                   |
| `bun run db:generate`   | Regenerate the Prisma Client.                       |
| `bun run db:migrate`    | Create a Prisma migration (dev).                    |
| `bun scripts/seed.ts`   | Insert DEMO-labeled seed content.                   |
| `bun test`              | Run the Vitest test suite (chronology, resume, RLS, attribution, scope). |

## Tests

Run `bun test`. The suite covers:

- `tests/chronology.test.ts` — learning events preserve actual chronological order; parent/child branching is preserved.
- `tests/resume.test.ts` — `getLastVisitedPoint` returns the actual last event + topic; resume opens at the right section.
- `tests/source-attribution.test.ts` — grounded answers cite real passages; missing coverage is flagged honestly.
- `tests/research-scope.test.ts` — `light` vs `deep` scope changes the number of pages fetched; user-controlled.
- `tests/preferences.test.ts` — preferences round-trip; onboarding flag toggles correctly.
- `tests/no-dark-mode.test.ts` — asserts no `dark:` Tailwind classes, no `.dark` CSS, no theme toggle in the codebase.

## Production deployment

The schema and API are portable to PostgreSQL/Supabase:

1. Swap `datasource db { provider = "postgresql" }` and update `DATABASE_URL`.
2. Add Supabase Auth and replace `getDemoUserId()` with the authenticated user id.
3. Add row-level security policies server-side (the schema already has `userId` on every user-owned model).
4. Replace local `uploads/` storage with Supabase private storage.
5. Add pgvector for embedding-based retrieval (the `SourcePassage.embeddingJson` field is already a JSON number array, ready to migrate to a vector column).

## Honest limitations

- The sandbox uses a single demo user (no real auth). The data model is per-user; the migration is a drop-in.
- PDF text extraction is not yet wired (only `text/plain` and `text/markdown` are indexed). PDFs store metadata honestly with a "not yet indexed" state.
- Mermaid diagrams are not rendered at runtime (the `VisualExplanation` shows the spec as a code block with a caption). This is intentional to avoid pulling in a heavy runtime dep; the spec is preserved for future rendering.
- Some web sources return 400/403 from upstream providers (e.g. Google blocking the page reader). These are saved honestly with their actual response title; the UI shows them as-is rather than hiding the failure.
